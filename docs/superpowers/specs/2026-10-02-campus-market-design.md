# 校园二手交易平台设计文档

日期：2026-10-02（v2，按评审意见修订）
课程：数据库原理作业
目标：开发一个包含数据库的可运行软件系统（Python + SQLite 的校园二手交易平台）

## 1. 项目概述

校园二手交易平台，面向校内学生。卖家发布闲置商品并定价，买家按商品名搜索、按价格区间和分类筛选，看中后在系统内下单，买家或卖家任一方确认后完成交易。不限品类，覆盖教材、数码、宿舍用品等校园常见闲置物。

作业硬性要求：（1）可以运行；（2）包含数据库，数据自行设计创建。

## 2. 技术栈

- Python 3.12
- Flask（网页应用，服务端渲染 HTML）
- SQLite（Python 标准库 `sqlite3`），原生 SQL，不使用 ORM
- 密码存储：`werkzeug.security` 哈希，不存明文
- 运行依赖只有 Flask；测试用标准库 `unittest`，不引入 pytest

项目结构（代码放在 `campus_market/`）：

```
campus_market/
├── app.py            # Flask 应用工厂 create_app + 路由 + 业务逻辑
├── database.py       # 连接数据库、建表、写入示例数据
├── schema.sql        # 建表 SQL
├── templates/        # HTML 页面
├── static/style.css  # 样式
├── requirements.txt  # 只有 Flask
└── tests/test_app.py # unittest 核心功能测试
```

数据库文件为 `campus_market/campus_market.db`。首次运行自动建库建表并写入示例数据；若文件已存在则不重复初始化。

应用用工厂函数 `create_app(test_config=None)` 创建，数据库路径可由配置注入。测试传入临时文件路径（不用 `:memory:`，因为 SQLite 的内存库每个连接互相独立，多连接下不可用）。

**SQLite 外键必须开启**：SQLite 默认 `foreign_keys=OFF`，外键约束形同虚设。`database.py` 每次建立连接后立即执行：

```sql
PRAGMA foreign_keys = ON;
```

## 3. 数据库设计

四张表。建表时声明主键、外键（`ON DELETE RESTRICT`）、非空、CHECK、DEFAULT 约束。系统无删除用户 / 商品的功能，外键用 RESTRICT 即可，防止意外级联删除。

金额一律用 `INTEGER` 存「分」，避免 REAL 浮点精度问题。界面按元录入展示，入库乘 100、出库除 100 格式化为两位小数。

### categories（分类）

| 字段 | 类型 | 约束 |
|---|---|---|
| id | INTEGER | 主键 |
| name | TEXT | 唯一、非空 |

七个固定分类：教材书籍、手机数码、数码配件、宿舍生活、交通出行、服饰运动、其他闲置。

### users（用户）

| 字段 | 类型 | 约束 |
|---|---|---|
| id | INTEGER | 主键 |
| username | TEXT | 唯一、非空 |
| password | TEXT | 非空（哈希值） |
| role | TEXT | 非空，CHECK role IN ('buyer','seller')，默认 'buyer' |
| contact | TEXT | 联系方式（微信 / 手机号） |
| created_at | TEXT | 非空，默认 `datetime('now')`（ISO8601） |

### items（商品）

| 字段 | 类型 | 约束 |
|---|---|---|
| id | INTEGER | 主键 |
| title | TEXT | 非空（商品名，搜索字段） |
| price | INTEGER | 非空，CHECK price > 0（单位：分） |
| condition | TEXT | 非空，CHECK condition IN ('全新','九成新','八成新','有使用痕迹') |
| description | TEXT | 商品描述 |
| status | TEXT | 非空，CHECK status IN ('在售','已预订','已售','下架')，默认 '在售' |
| category_id | INTEGER | 外键 → categories.id（RESTRICT），非空 |
| seller_id | INTEGER | 外键 → users.id（RESTRICT），非空 |
| created_at | TEXT | 非空，默认 `datetime('now')`（ISO8601） |

### orders（订单）

| 字段 | 类型 | 约束 |
|---|---|---|
| id | INTEGER | 主键 |
| item_id | INTEGER | 外键 → items.id（RESTRICT），非空 |
| buyer_id | INTEGER | 外键 → users.id（RESTRICT），非空 |
| price | INTEGER | 非空，CHECK price > 0（成交价快照，单位：分） |
| status | TEXT | 非空，CHECK status IN ('待交易','已完成','已取消')，默认 '待交易' |
| created_at | TEXT | 非空，默认 `datetime('now')`（ISO8601） |

### 索引

```sql
CREATE INDEX idx_items_market ON items(status, category_id, price);
CREATE INDEX idx_orders_buyer ON orders(buyer_id);
CREATE INDEX idx_orders_item ON orders(item_id);
```

### 示例数据

首次运行写入：7 条分类、约 10 个用户（买家 / 卖家混合，买家不兼任所购商品的卖家）、约 30 件商品（覆盖各分类、不同价格带）、若干订单。示例数据保证状态一致：

- 订单「待交易」→ 对应商品「已预订」
- 订单「已完成」→ 对应商品「已售」
- 订单「已取消」→ 对应商品「在售」

## 4. 页面与功能

1. **首页 / 商品市场**：分类标签栏（7 类可点，可不选）+ 商品名搜索框 + 价格区间（最低价 / 最高价）+ 商品卡片列表（商品名、价格、成色、分类、卖家）。三个筛选条件可任意组合，也可只用其一。搜索框留空表示不按名称过滤；价格留空表示不限该端（只填最低价即为「≥ 最低价」）。**市场只显示 `status='在售'` 的商品**。
2. **商品详情页**：完整信息 + 卖家联系方式（**仅登录后可见**，未登录只显示商品信息）+ 「购买」按钮（当前身份为买家、商品在售、且不是自己发布的商品时显示）。
3. **注册页**：用户名、密码、联系方式，注册后默认买家身份。用户名重复时提示已存在。
4. **登录页**：用户名 + 密码。
5. **发布商品页**（卖家）：商品名、分类下拉、价格（元，两位小数）、成色下拉、描述。
6. **我的商品页**（卖家）：自己发布的商品列表。「在售」商品可改价、可下架；「已预订」不可改价下架；「已售」作为成交记录保留，不支持改价下架；「下架」为终态，不再提供重新上架。
7. **我的订单页**（买家）：自己下的单。「待交易」可取消、可确认完成；「已完成」「已取消」只读。
8. **卖出记录页**（卖家）：别人买自己商品的订单。「待交易」可确认完成；「已完成」「已取消」只读。
9. **设置页**：一键切换买家 / 卖家身份（改 `users.role`，立即生效）；修改联系方式。

导航栏随当前身份变化：买家显示「商品市场 / 我的订单 / 设置」，卖家显示「商品市场 / 发布商品 / 我的商品 / 卖出记录 / 设置」。导航栏隐藏只是展示优化，**权限一律以服务端路由校验为准**。

## 5. 业务规则

- 当前身份为买家才能下单、取消订单、看「我的订单」；当前身份为卖家才能发布、改价、下架、看「我的商品」「卖出记录」。身份可在设置页随时切换。
- 订单「待交易 → 已完成」由**买家或卖家任一方确认**即完成（两侧页面各有一个「确认完成」按钮，不设双向确认字段）。
- 订单「待交易 → 已取消」仅买家可取消。「已完成」「已取消」为终态，不再流转。
- 不能购买自己发布的商品（按 `item.seller_id` 与当前用户 id 比较，与身份无关）。
- 商品状态流转与订单联动：
  - 下单成功：商品 `在售 → 已预订`
  - 订单完成：商品 `已预订 → 已售`
  - 订单取消：商品 `已预订 → 在售`
- 只有商品发布者本人能改价、下架自己的商品（路由层强制校验）。
- 商品状态为「已预订」时不可改价、不可下架、不可再次下单；「已售」商品不在市场显示，作为成交记录保留。
- 「下架」商品不出现在市场列表，仍可在「我的商品」中看到。

### 下单的原子性（防超卖）

两个买家同时下单同一商品时，不能各自先查再改。用单条条件更新抢占，放在事务里：

```sql
BEGIN;
UPDATE items SET status='已预订' WHERE id=? AND status='在售';
-- 受影响行数为 0 → 抢占失败，回滚并提示「商品已被买走或已下架」
INSERT INTO orders(item_id, buyer_id, price, status) VALUES(?, ?, ?, '待交易');
COMMIT;
```

订单完成、取消同样在事务内联动更新商品状态。同一件商品同一时刻至多存在一个「待交易」订单，由上述原子更新保证。

## 6. 错误处理

- 登录态用 Flask session，**session 只存 `user_id`**；每个请求从数据库读取用户和当前 `role`，保证设置页切换身份后立即生效，不残留旧角色。
- 未登录访问发布、订单、设置等页面时跳转登录页。
- **路由强制鉴权**：买家身份访问「发布商品 / 我的商品 / 卖出记录」返回 403 并提示；卖家身份访问「我的订单」同样 403；非商品发布者提交改价 / 下架返回 403。不能只靠导航栏隐藏按钮。
- 所有 SQL 使用参数化查询，防注入。商品名模糊搜索用 `LIKE ... ESCAPE '\'`，用户输入的 `%`、`_`、`\` 先转义，防止通配符注入干扰筛选。
- 表单校验失败返回页面并提示原因，不崩页：
  - 用户名、密码非空；用户名重复提示已存在
  - 价格为正数，最多两位小数，按元录入后乘 100 转为分
  - 价格区间必须为合法数字，且**最低价 ≤ 最高价**
  - 下单条件不满足时提示（商品已售 / 已预订 / 下架、买自己的商品、身份不对等）
- Flask 设置 `app.secret_key`（开发环境用固定常量，文档注明生产环境应改为环境变量注入）。
- 商品详情页卖家联系方式仅登录后可见，避免联系方式对匿名访客公开。

## 7. 测试

用标准库 `unittest` + Flask test client。`create_app` 支持注入数据库路径，测试每个用例组使用独立临时文件数据库（不用 `:memory:`）。

覆盖链路：

- 注册、登录、身份切换后权限立即变化
- 发布商品、改价、下架；非发布者改价 / 下架返回 403
- 搜索（商品名模糊，含 `%` 特殊字符输入）、价格区间筛选（含最低价 > 最高价的非法输入）、分类筛选及组合查询
- 市场只显示「在售」商品（已售、已预订、下架均不出现）
- 下单成功后商品变为「已预订」
- 不能买自己的商品；不能重复下单同一商品
- 直接 POST 下单已售 / 已预订 / 下架商品被拒绝
- 订单取消后商品恢复「在售」
- 订单确认完成后商品变「已售」
- 未登录访问受保护页面跳转登录；越权访问他人商品操作返回 403
- 非法订单状态流转被拒绝（如对「已取消」订单再确认）
